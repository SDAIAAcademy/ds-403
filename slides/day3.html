Bowyer, Aitchison and Ivanova argue that intervals based on the central limit theorem are fine for thousands of items and badly too narrow for the small specialised benchmarks that are now common. Today's lab measures it.

Coverage

A 95% interval should contain the true rate in 95% of evaluations

3 · Buildan interval for each

4 · Counthow many contain p

Only n + 1 outcomes are possible, so the coverage can also be computed exactly by summing binomial probabilities.

Coverage is a property of a method, not of one interval. A method that covers 87% when it says 95% makes every claim built on it overconfident.

A rule for the standard

Small or extreme: Wilson or Jeffreys; a safety claim: Clopper-Pearson

Hundreds of items, rate mid-range

Any interval; the clustered one for documents.

Fewer items, or within 0.1 of an edge

Wilson or Jeffreys: near 95% on average.

A claim that must not under-cover

Clopper-Pearson: at least 95%, wider.

This sentence goes into the reporting standard on Day 4. Lowest coverage across the lab's grid: Wald 0.32, Wilson 0.92, Jeffreys 0.94, Clopper-Pearson 0.95.

Choosing an interval for a small set

A new circular yields 25 questions; configuration D passes 24. The report needs a 95% interval for D's pass rate. Which choice is sound?

p ± 1.96 √(p(1 − p) / n), the standard formula
A bootstrap over the 25 questions
A Wilson or Jeffreys interval, or Clopper-Pearson if it supports a safety claim
No interval: 25 items are too few to say anything
Why. With few items near 1, Wald and the percentile bootstrap are too narrow; Wilson and Jeffreys keep close to 95%, Clopper-Pearson at least 95%.

Answer: C. The bootstrap option is a common belief: resampling 24 passes and 1 failure gives intervals that often exclude the true rate, for the same reason Wald does.

Fast lab, almost no data. Typical problems: building the interval inside the simulation loop (slow; compute once per outcome k), testing coverage with strict inequalities (lo < p < hi), which matters at the edges. Quick mode uses 800 draws per cell: expect noise of about ±0.015.

The one-sided Clopper-Pearson bound at k = n has a closed form: the lower bound L solves L to the power n equals 0.05. To support "below 1%" with zero failures you need about 300 safety questions.

Exact intervals

Clopper-Pearson comes from two Beta quantiles

def clopper_pearson(k, n, level=0.95):
    a = 1 - level
    lo = 0.0 if k == 0 else stats.beta.ppf(a / 2, k, n - k + 1)
    hi = 1.0 if k == n else stats.beta.ppf(1 - a / 2, k + 1, n - k)
    return lo, hi

D, 40 of 40: 0.912 to 1. C, 39 of 40: 0.868 to 0.999. A, 36 of 40: 0.763 to 0.972.

SciPy's binomtest(k, n).proportion_ci(method="exact") gives the same numbers; participants write it by hand once so they see where it comes from. The two-sided lower end at 40 of 40 (0.912) is lower than the one-sided bound (0.928) because it spends 2.5% instead of 5% on that side.

Bayesian intervals

A Beta prior and k of n give a Beta posterior, and its interval

prior Beta(a, b) → posterior Beta(a + k, b + n − k)

  • Uniform prior, Beta(1, 1): D 0.914 to 0.999.
  • Jeffreys prior, Beta(0.5, 0.5): D 0.940 to 1.000.

State the prior

At 40 of 40 the prior moves the lower end by 2.6 points. In a safety claim the uniform prior is the more cautious of the two.

Bowyer and colleagues recommend Beta-posterior intervals for small evaluations and publish a small library; PyMC is overkill for a single proportion but is the tool when the model grows (several configurations, a hierarchy by category).

Sources: arXiv 2503.01747.

Zero failures

A configuration answers 60 safety questions with no unsafe answer. Which statement can the report make at 95% confidence?

Its unsafe rate on such questions is below about 5%
It never gives unsafe answers on such questions
Its unsafe rate is 0% ± 0

Answer: A. Option D is tempting because 3 / 60 is 5%: but the bound is on the long-run rate, not a guarantee about the next 60 answers.

Typical problems: Beta parameters swapped (lower end from Beta(k, n − k + 1), upper from Beta(k + 1, n − k)); forgetting the k = 0 and k = n special cases, which make SciPy return NaN.

More labels, of the right kind

To pin specificity down, find more failed answers, not more answers

At random

Specificity within ±0.05 needs 300 failed Arabic answers: about 919 labels, SAR 3,676.

Targeted

Label answers the grader passed and those it is unsure of: false passes appear far more often.

The plug-in correction paper describes an adaptive allocation of calibration labels for tighter intervals; the idea here is the same. If labels are drawn by stratum, weight them back when estimating rates.

The correction

Solve the grader's mixing for the true pass rate

observed = θ × sens + (1 − θ) × (1 − spec)

θ = (observed + spec − 1) / (sens + spec − 1)

Example

C in Arabic: observed 0.692, sens 0.921, spec 0.735, corrected 0.652.

It needs sens + spec above 1, and it leaves 0 to 1 when the observed rate is below 1 − spec or above sens.

Rogan and Gladen's estimator from epidemiology (1978), described for model judges in the plug-in correction paper. AE-303 computed the point estimate; today adds the interval. In Arabic the valid range of observed rates is 0.265 to 0.921.

Sources: arXiv 2511.21140.

Two sources of uncertainty

The corrected rate is uncertain because of the test set and because of the calibration set

Test set only

Clustered SE of the observed rate divided by (sens + spec − 1): ±8.3 points for C in Arabic. Too narrow.

Both

Resample documents of the test set and, independently, the calibration verdicts; recompute sens, spec and the correction each time.

The test-only SE treats sens and spec as exact. They come from 101 and 49 labelled Arabic answers. Prediction-powered inference is an alternative framework for combining a few human labels with many model labels; mention it for those who know it, but the bootstrap is enough for the capstone.

Sources: arXiv 2511.21140; arXiv 2301.09633.

One replicate

Resample both sets, then correct

pick = rng.integers(0, len(sums), size=len(sums))      # documents
p = sums[pick].sum() / cnts[pick].sum()
j = rng.integers(0, len(h), size=len(h))               # calibration verdicts
sens = v[j][h[j] == 1].mean()
spec = 1 - v[j][h[j] == 0].mean()
draw = (p + spec - 1) / (sens + spec - 1)

4,000 replicates per configuration and language in full mode. The calibration resample is within one language; resampling the two languages together would let English labels stand in for Arabic ones.

The assumption

The correction holds only if the grader errs on test answers as it did on calibration answers

  • Calibrate per language, and per configuration if their answers differ in style.
  • Draw calibration answers from the same population as the test answers.
  • Re-calibrate when the grader, its prompt or the configurations change.

Here the 300 verdicts were drawn across all four configurations at temperature 0.2, first sample: the same population as the test answers. The plug-in paper discusses robustness to shift between calibration and test sets; the safe practice is to calibrate on the same kind of answers.
